# How the API catalogue works - steps, artifacts, waits, folders

> Commands and prompts: [HOW-TO-RUN.md](HOW-TO-RUN.md) · Data protection and approvals: [SECURITY-AND-GOVERNANCE.md](SECURITY-AND-GOVERNANCE.md)

## 1. The flow at a glance

| # | Step | Who runs it | Needs (input) | Produces (artifact) | Then |
|---|---|---|---|---|---|
| 0 | Set-up (once) | you | – | `api-catalog.config.yaml` per app, `domains.xlsx`, ACORD files, style examples, `regions/<REGION>.yaml` | – |
| 1 | **Discovery** | agent `api-discovery` (`/discover-apis`) | .NET source, style examples | `discovery/<REGION>/<app>/openapi.yaml` (+ inventory, report) | automatic loop until validation passes |
| 2 | **Analysis** | agent `api-analysis` (`/analyze-apis`) | step 1 spec + domain Excel | `analysis/<REGION>/<app>/` 1-enriched OpenAPI, 2-domains & capabilities, 3-entities & attributes, 4-duplicates | automatic loop |
| 3 | **Regional view** | agent `regional-view` (`/build-regional-view`) | all step 2 folders + `external/` specs | `regional-view/regional-view.html/.xlsx`, `spec-viewer.html` | automatic loop |
| 4 | **ACORD alignment** | agent `acord-alignment` (`/align-acord`) | step 3 data + ACORD + (baseline) | `alignment/<REGION>/acord-alignment.html/.xlsx` | automatic loop, then **WAIT** |
| 5 | **Human review** | architects / data owners | step 4 HTML or Excel | `review-decisions.json` or filled `.xlsx` → `/import-review` → `approvals.yaml` | **the only manual step** |
| 6 | **Canonical model** | agent `canonical-model` (`/build-canonical`) | step 5 approvals | `canonical/<REGION>/` canonical-openapi.yaml/.json, canonical-model.json/.yaml/.xlsx, mapping, viewer | automatic loop; `--release` when you say so |
| 7 | **Next region** | same as 4-6 | `baseline:` = released canonical of the first region | `alignment/UK/…`, `canonical/UK/…` | waits for the first region's **release** |
| 8 | **Global canonical** | agent `canonical-model` (`/build-global-canonical`) | all released region canonicals | `canonical/GLOBAL/` global model + OpenAPI + explorer | automatic |

`/run-api-catalog` (agent `api-catalog`) runs 1 → 8 in order and stops at every wait.

## 2. What you wait for (and what you don't)

| Wait | Why | How it ends |
|---|---|---|
| **Review after step 4** | Approvals are human-only; agents never approve | Reviewers decide in the HTML (*Approve all…* or per entity) or Excel, export/save, run `/import-review` |
| Re-review after a source change | an approval whose row changed becomes **changed**; canonical drops to *draft* | reviewers decide the changed rows again |
| **Release** of a region (`--release`) | other regions and the global model only use frozen releases | you ask the canonical agent to release (version from `regions/<REGION>.yaml`) |
| Next region | UK aligns against EU's **released** canonical | EU release exists |
| Loop limit reached | a validator kept failing after `maxIterations` | the agent reports the open errors - fix inputs (code, overrides, Excel) and rerun |

Everything else (scan, build, analyse, aggregate, align, build canonical, merge) runs straight through with its
validator loop; each stage starts only when the previous stage's `validation.json` says `pass`.

## 3. Artifact order (what comes after what)

```
source code ─▶ inventory.json ─▶ openapi.yaml ─▶ 1-openapi.enriched.yaml
                                               ├▶ 2-domains-capabilities ─┐
                                               ├▶ 3-entities-attributes   ├─▶ regional-view-data.json ─▶ regional-view.html/.xlsx
                                               └▶ 4-duplicates-report    ─┘                          └▶ spec-viewer.html
regional-view-data.json + ACORD (+ baseline) ─▶ alignment.json ─▶ acord-alignment.html/.xlsx
        ─▶ [people decide] ─▶ approvals.yaml ─▶ canonical-model.json/.yaml + canonical-openapi.yaml/.json
        ─▶ releases/<version>/ ─▶ (baseline of next region) ─▶ … ─▶ canonical/GLOBAL/*
```

## 4. Folder map (central `api-catalog/` folder)

```
api-catalog/
  global.yaml                      optional: global version/title, pinned region versions, requireReleased
  domains.xlsx                     business domain catalogue (you) -> domains.json (generated)
  style-examples/                  HOUSE STYLE examples - reference only, never copied
    _global/*.yaml                 all regions
    EU/*.yaml   UK/*.yaml          region-specific additions
  reference/
    acord/                         YOUR licensed ACORD model: xlsx / xsd / yaml / json, one file or many
    acord.reference.json           generated by load_reference.py
    synonyms.yaml                  your vocabulary for matching
  regions/
    EU.yaml  UK.yaml               one per region: ACORD source, baseline, thresholds, canonical version
  configs/                         central mode: one api-catalog config per application (repoRoot -> app repo)
  external/<REGION>/<app>/openapi.yaml   specs of apps you cannot scan (you drop them)
  discovery/<REGION>/<app>/        step 1 (generated) + overrides.yaml (agent)
  analysis/<REGION>/<app>/         step 2 (generated) + decisions.yaml (agent)
  regional-view/                   step 3 (generated)
  alignment/<REGION>/[<slice>/]    step 4 (generated) + alignment-overrides.yaml (agent) + approvals.yaml (people via import)
  canonical/<REGION>/              step 6 (generated) + releases/<version>/ (frozen)
  canonical/GLOBAL/                step 8 (generated)
```
**All YAML for a region** lives under the region name: `regions/<REGION>.yaml` (settings),
`style-examples/<REGION>/` (style), `external/<REGION>/` (dropped specs), and the generated
`discovery|analysis|alignment|canonical/<REGION>/`. ACORD is one standard, so it sits once in `reference/acord/`.

## 5. Adding a region (e.g. UK, then APAC)
1. Application configs with `region: UK` (or drop specs into `external/UK/<app>/`).
2. Optional `style-examples/UK/`.
3. `regions/UK.yaml` from the template with `baseline: ../canonical/EU/releases/1.0.0/canonical-model.json`.
4. Run steps 1-3 for the UK apps, then 4-6 for UK. Baseline entities are reused unchanged; UK only adds.
5. Release UK, then rebuild the global canonical. APAC can use EU or UK (or the global model's region) as baseline.

## 6. Global canonical: filter by region and API
`canonical/GLOBAL/global-canonical.html`:
- **Regions** chips + "region means": *used by the region's APIs* or *available in the region's canonical*
- **Applications** chips (EU/claims, EU/policy, UK/quote …), **Domain**, **Origin** (ACORD-based / custom), search (API path, operationId, entity, attribute)
- Tabs: entity × region matrix, entities & attributes (per-region availability and usage), endpoints, and the
  **filtered OpenAPI spec as YAML or JSON** with copy/download - e.g. "UK only, quote API" downloads exactly that slice.
